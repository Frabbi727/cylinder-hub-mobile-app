Web App vs Mobile App — Key Differences
The web app serves the same salesman role but provides a larger screen experience for when the salesman is at a desk, counter, or depot — not in the field. Both apps share the same API but the web app has more space for data, tables, and detailed reporting.

Design System — Web
Design Direction
Theme: Clean professional — sidebar layout, data-forward, works at 1280px minimum width.
Feel: A business tool not a consumer app — reliable, clear, information-dense but not cluttered.
Sidebar: 240px fixed left sidebar with logo, nav links, and user info at bottom.
Content area: fluid width, max-content 1200px, padding 24px.
Typography: Readable at all zoom levels — important for salesmen who may use large text.

The main home page. Full overview of today at a glance.

Section: Today&apos;s Allocations — one card per cylinder type

Page 3: New Sale  ·  Route: /sales/new

[ROW]

Success: green toast notification + redirect to /sales/{id}
API: GET /customers (autocomplete), POST /customers (new), POST /sales

Page 9 — Empty Cylinders
Page 9: Empty Cylinders  ·  Route: /empties
Log all empty cylinder collections — normal and extra.
[ROW]
Page header: Empty Cylinders title, Log Empty Return button top right
Summary cards: Total Empties Collected Today / Total Empties This Week / Pending Verification (extras)
Stock snapshot table: each cylinder type with filled qty / empty in warehouse / with customers
Log Empty Return button: opens modal with two tabs — Normal Return and Extra Return
Normal Return modal: Cylinder type (dropdown), Customer (searchable), Qty, Date, Notes — Submit
Extra Return modal: same fields + Reason dropdown (Old stock / Neighbour collection / Competitor cylinder / Salesman handover / Other) + extended Notes
Extra return warning text: Admin will be notified for verification
Today&apos;s Collections table: Time, Customer, Cylinder type, Qty, Type (Normal/Extra), Status (Verified/Pending)
Extra returns show EXTRA badge in purple — Pending verification in orange
Full history tab: all empty returns ever with filters
Per-customer pending empties table: which customers still have empty shells
API: GET /stock, POST /returns, POST /returns/extra
Page 10 — End of Day
Page 10: End of Day  ·  Route: /eod
Daily reconciliation. One wizard per allocation. Submit before midnight.
[ROW]
Page header: End of Day — [today&apos;s date]
Allocation cards: one card per allocation today — each shows current status
Card states: Pending (orange) / In Progress / Reconciled (green tick)
Click on any pending card: opens the reconciliation form for that allocation
Reconciliation form (in-page panel, not modal — big enough for desktop):
  Allocation summary row at top: Cylinder type, Allocated qty, Current sold_qty from sales
  Step 1 — Confirm Sold Qty: pre-filled from actual sales, editable with warning if mismatch
  Step 2 — Empty Cylinders: split into Regular (from today sales) and Extra (others collected)
  Step 3 — Cash Submitted: amount input, pre-filled from paid sales total, editable
  Preview table: Allocated / Sold / Regular Empties / Extra Empties / Unsold (auto-calc) / Cash
  Unsold cylinders auto-calculated and shown: these will return to warehouse stock
  Warning if cash submitted is significantly less than expected (>10% gap)
  Submit Reconciliation button — teal, disabled until all fields filled
After submission: card turns green with Reconciled badge — cannot re-open
If all allocations reconciled: full-page success state with summary of the day
API: POST /allocations/{id}/reconcile

Empty Cylinder Web Feature — Complete Flow
Why This Needs Special Attention
Empty cylinder collection is a critical asset tracking feature.
The web app gives salesmen the most complete tool to log, track, and verify empties.
Two types: Normal returns (expected) and Extra returns (unexpected — needs admin approval).
Every empty cylinder is worth TK 300-500 as a physical asset.
